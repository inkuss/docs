## Dokumentation für einen System-Upgrade

Dies ist eine Dokumentation für einen System-***Upgrade***, keine Neuinstallation.

* Es wird angenommen, dass du bereits erfolgreich ein FOLIO-System auf einem Einzelserver aufgesetzt hast und jetzt zu einer aktuelleren Version von FOLIO migrieren möchtest.

* Diese Dokumentation behandelt den Upgrade einer Distribution "platform-complete".

## Systemvoraussetzungen

**Systemversionen**

| **Systemtyp**                       | **Version für diese Dokumentation**        |
|-------------------------------------|--------------------------------------------|
| Betriebssystem                      | Ubuntu 22.04.2 LTS 64-bits                 |

## I. Vor dem Upgrade

### I.i) Ubuntu Upgrade
Erst Ubuntu Updates & Upgrades machen. Das auch auf dem Datenbankserver machen.
Den Reboot des DB-Servers erst machen, wenn der "normale" Server wieder hoch gekommen ist und alle Container wieder laufen !  
  sudo apt update
  sudo apt upgrade
  sudo reboot

Prüfe, ob alle Dienste nach dem Reboot neu gestartet wurden: <em>Okapi, postgres, docker, the docker containers</em> (do: docker ps --all | more ) <em>, Stripes and nginx.</em>

### II.iv) Konfiguriere die Umgebungsvariablen der Module
  Auf diesem Teil wird ein Systemadministrator vermutlich die meiste Zeit aufwenden.

  Überprüfe die Umgebungsvariablen für Okapi:

 curl -X GET http://localhost:9130/_/env

  In der Folge, re-konfiguriere die Umgebungsvariablen so wie benötigt.
  Folge diesen Anweisungen um eine Umgebungsvariable für ein Modul zu ändern: [Change Environment Variables of a Module](https://wiki.folio.org/display/SYSOPS/Change+Environment+Variables+of+a+Module).

#### i. Setze neue globale Umgebungsvariablen
  Setze die Umgebungsvariable ENV auf ENV = ramsons . Wenn du nur einen einzigen Mandanten auf dem System betreibts, brauchst du dies nicht zu machen. Die Variable hat dann den Standardwert ENV = folio. Wir setzen es trotzdem.

  curl -w '\n' -D - -X POST -H "Content-Type: application/json" -d "{\"name\":\"ENV\",\"value\":\"ramsons\"}" http://localhost:9130/_/env

Setze INNREACH_TENANTS - ansosnten wir mod-inn-reach für deinen Mandanten nicht anstarten:

curl -w '\n' -D - -X POST -H "Content-Type: application/json" -d "{\"name\":\"INNREACH_TENANTS\",\"value\":\"diku|bthvn\"}" http://localhost:9130/_/env

Wenn du mehrere Mandanten hast, trenne ihre Namen durch ein "|" im Wert der INNREACH_TENANTS Variablen.

KAFKA_HOST und KAFKA_PORT müssen in /env gesetzt sein, sonst kommt mod-users nicht hoch.

Setze DB_CONNECTION_TIMEOUT mindestens auf 250, sonst kommt mod-entities-links nicht hoch.
